# Configuration

PTU-Net experiments use a validated YAML document. Paths, dataset splits, compressor routing, model choices, optimization, evaluation, and optional tracking are recorded together so a run can be reconstructed later.

## Path resolution

Relative `data_root` and `output_root` values are resolved from the directory containing the YAML file, not from the shell's working directory. Home-directory and environment-variable expansion are supported. Loading fails when an environment variable remains unresolved.

Prefer a relative path or an environment variable over a private absolute host path. Keep the output root separate from immutable input data.

## Minimal structure

This example defines the data contract and relies on package defaults for the model and trainer:

```yaml
name: local-example

paths:
  data_root: ../data
  output_root: ../outputs

datasets:
  - name: synthetic
    variable: SYNTH
    resolution_tag: 64x96
    shape: [64, 96]
    timestep_digits: 4
    splits:
      train: {start: 1, end: 8}
      validation: [10, 11]
      test: [13, 14]
    compressors:
      even: sz3
      odd: zfp
```

Timestep ranges include both `start` and `end`. A positive `step` can be added. Explicit lists and inclusive ranges are both accepted. Training, validation, and test timesteps must not overlap within a dataset.

## Top-level sections

| Section | Purpose |
| --- | --- |
| `name` | Experiment identifier used in records and output organization |
| `paths` | Machine-local input and output roots |
| `datasets` | Field shape, filename templates, splits, and compressor assignment |
| `compressors` | Compressor-key to filename-suffix mapping |
| `model` | Architecture and ablation settings |
| `training` | Optimizer, scheduler, precision, seed, device, and loss settings |
| `evaluation` | Batch size, temporal search radius, metric chunk size, and data range |
| `tracking` | Optional external experiment tracking |

Unknown keys are rejected rather than silently ignored.

## Dataset templates

The default templates reproduce the filename pattern described in [data-contract.md](data-contract.md). Templates can use these values:

```text
name, variable, resolution_tag, height, width,
timestep, timestep_index, compressor, extension
```

Template output must remain below the configured root. Absolute paths and paths that escape through `..` are rejected.

The default compressor keys are `sz3`, `sz`, `szp`, `sperr`, `hpez`, `zfp`, `mgard`, and `fpzip`. A `compressors.extensions` mapping can add or replace suffixes. Compressor keys name file conventions only. They do not prove that a file was produced by the named compressor.

## Core defaults

The architecture defaults inherited from the original implementation are:

```yaml
model:
  patch_size: 32
  stride: 16
  subpatch_size: 8
  embed_dim: 384
  num_heads: 12
  num_layers: 8

training:
  epochs: 300
  batch_size: 32
  learning_rate: 0.0005
  weight_decay: 0.001
  seed: 42
  device: auto
```

`patch_size` must be divisible by `subpatch_size`, `embed_dim` must be divisible by `num_heads`, and stride cannot exceed patch size. `device: auto` selects CUDA when PyTorch reports it as available and otherwise selects CPU. Set `device: cpu`, `device: cuda`, or an explicit value such as `cuda:1` when automatic selection is not appropriate.

The full validated schema is defined by the dataclasses in [`src/ptunet/config.py`](../src/ptunet/config.py). Defaults describe code behavior and are not a recommended scientific protocol.

## Ablations

The `model` section includes explicit switches for the adaptive baseline, transformer correction, positional embedding, U-Net refinement, skip attention, and squeeze-excitation blocks. Record the resolved configuration for every ablation. Change one defined factor at a time unless the study design calls for an interaction analysis.

Optional gradient and spectral loss weights default to zero. Enabling them changes the training objective and should be treated as a separate experiment condition.

## Overrides

The configuration loader accepts dotted overrides such as:

```text
training.epochs=20
training.device=cuda:0
model.use_unet_refinement=false
datasets.0.compressors.even=zfp
```

Values are parsed as YAML, so booleans and numbers retain their types. Save the fully resolved configuration with the output rather than relying on shell history alone.

The output of `ptunet show-config` uses the same canonical schema accepted by the loader. It can be redirected to a file and loaded again. Its paths are absolute after resolution, so inspect them before moving or sharing the file.

## Tracking

External tracking is disabled by default. Enabling it requires the optional tracking dependency and an explicit project configuration. Do not place API keys in YAML. Use the tracking service's supported credential mechanism and keep a local machine-readable record even when remote tracking is enabled.
